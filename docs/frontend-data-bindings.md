# Frontend Component-to-Data Binding Contract

This document provides the authoritative binding map between frontend UI components and backend C++20 engine sources in Fort ("Corridor"). Every metric, state, badge, and interaction is bound to verified backend sources without fabricated values.

| UI Element | Screen | Backend Source (File + Field/Endpoint) | Type / Units | Update Mechanism | Failure / Degraded / Empty State |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Bid / Ask Price Ladder** | Live Order Book | `luv_lob.hpp`: `PriceLevel` (`PriceLevel::price`, `PriceLevel::total_qty`, `OrderSlot`) | Bids: descending, Asks: ascending. Price: fixed-point $\times 10^4$. Qty: int64 | In-process LOB state; REST initial / WS stream | `<EmptyState>` when no symbol selected; frozen book + `"FEED STALLED"` banner when feed age > 100ms |
| **Depth Bars** | Live Order Book | `luv_lob.hpp`: `PriceLevel::total_qty` relative to visible max | Percentage width (0–100%) | LOB updates | Background bar rendered at 0% depth if level is empty |
| **Bid-Ask Spread** | Live Order Book | `luv_lob.hpp`: `best_ask().price - best_bid().price` | Fixed-point price difference / bps | Computed on every tick | Displays `"—"` when book side has zero depth |
| **Feed Connection Badge** | Global Shell / Order Book | `luv_telemetry.hpp`: `run_health_checks` (`feed_fresh`, age < 100ms) + `/healthz` | Enum: `connected` (ok), `reconnecting` (warn), `stalled` (critical) | Polling `/healthz` & `/metrics` (3s) | Displays `<StatusChip>` in `--status-critical` with timestamp of last message |
| **Order Entry Ticket** | Execution | `luv_execution.hpp`: `exec::OrderIntent`, `PreTradeRisk` | Symbol (0..511), Side (`buy`/`sell`), Type (`market`/`limit`), Qty (uint64), Price (dec/fixed-point) | REST `POST /api/v1/orders` (Bearer auth) | Inline field validation against `RiskLimits`; rejects shown verbatim; button disabled on halt |
| **Order State Chip** | Execution | `luv_http_server.hpp`: `OrderStatus`, `luv_execution.hpp` | Enum: `pending`, `live`, `partial`, `cancelled`, `done`, `rejected`, `not_found` | Optimistic `pending` -> WebSocket stream / REST query | Rejection displays exact backend reason (`RejectQty`, `RejectPosition`, `RejectHalted`, etc.) |
| **Order Event History Drawer** | Execution | `luv_websocket.hpp`: `FillEvent` stream + `OrderStatus` transitions | Order ID, fill price ($\times 10^4$), filled qty, timestamp_ns | Native WebSocket `GET /api/v1/stream/{order_id}` | Shows `"No fill notifications received"` if unfilled; connection error flagged if WS closes |
| **Active Positions Table** | Execution | `luv_http_server.hpp`: `GET /api/v1/positions` | `symbol_idx` (0..511), `net_position` (int64), `gross_exposure` (int64) | REST polling / manual refresh | Displays `<EmptyState>` when zero positions held |
| **Throughput Gauge & Chart** | Telemetry | `luv_telemetry.hpp` / `/metrics`: `luv_execution_tick_rate_hz` | Gauge (events / sec) | REST `/metrics` (3s interval) | Blank chart + `"—"` with `"Telemetry unavailable"` notice on scrape failure |
| **Latency Indicators** | Telemetry | `luv_telemetry.hpp` / `/metrics`: `luv_execution_risk_check_latency_nanoseconds`, `luv_execution_inference_latency_microseconds` | Risk check: ns; Inference: μs | REST `/metrics` (3s interval) | Labeled explicitly with units; disclaimer caption noting local compute vs production SLA |
| **Cumulative Counters** | Telemetry | `luv_telemetry.hpp` / `/metrics`: `luv_execution_fills_total`, `luv_execution_rejections_total`, `luv_websocket_fill_notification_drops_total` | Monotonic uint64 counters | REST `/metrics` (3s interval) | `"—"` when metrics endpoint unreachable |
| **Arena Memory Pressure** | System Health | `luv_arena.hpp`: `occupancy_ratio()`, `pressure_tier()` | Percentage (0–100%): Normal (<70%), Warning (70-84%), ShedLoad (85-94%), EmergencyHalt (≥95%) | System health query / metrics | Visually escalates to `--status-warn` at 70% and `--status-critical` at ≥85%/95% |
| **Circuit Breaker State** | System Health | `luv_safety.hpp`: `CircuitBreakerState` (`kClosed`, `kOpen`, `kHalfOpen`) | Enum: `kClosed` (Normal/OK), `kHalfOpen` (Probing/Warn), `kOpen` (Tripped/Critical) | Telemetry / Risk gateway status | Red critical alert when Tripped/Open; read-only control badge |
| **API & Service Health** | System Health | `/healthz` HTTP endpoint (port 9090) | HTTP 200 `ok\n` | REST polling (5s interval) | Shows `--status-critical` `"Unavailable"` on non-200 or timeout |
| **K8s Pod Status** | System Health | Out of scope / un-wired | Pod status descriptor | Fixed indicator | Explicitly marked `"Not yet wired / Simulation Host"` (no fake pod counts) |
| **Recovery Ledger Table** | Audit Trail | `luv_safety.hpp` (`AuditEvent`), `luv_recovery.hpp` (`RecoveryLedger`) | Sequence (uint64), Event (`kAdd`, `kFill`, `kCancel`, etc.), Order ID, Qty, Price, Timestamp ns, Checksums | Local binary file stream (`/api/corridor/ledger`) | Shows `<EmptyState>` with error message if file unconfigured or corrupt; CSV export |
| **Maturity & Readiness Panel** | Pilot Summary | `INVESTOR_READINESS_BRIEF.md`, `CAPABILITIES.md`, `KNOWN_ISSUES.md` | Stage: Research Simulator / Parked. Validated vs Out-of-Scope matrices | Static verified capability documentation | Persistent `<SandboxWatermark>` rendered across all simulated data views |
| **Sandbox Watermark** | Global / All Screens | `README.md`, `INVESTOR_READINESS_BRIEF.md` | Non-dismissible top-banner and watermark badge: `"SIMULATED DATA · RESEARCH SIMULATOR"` | Constant | Always visible in SIMULATION / PAPER mode |
